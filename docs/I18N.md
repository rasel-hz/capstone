# Language system

Khowayk is one app in two languages: Saudi Arabic (`ar-SA`, the default) and English (`en`). Both use the same components, games, art and logic. It runs on `i18next` and `react-i18next`.

## How it works

| Piece | Where | What it does |
|---|---|---|
| Locale files | `src/i18n/locales/<lang>/<area>.json` | All interface text, one file per area |
| Setup and helpers | `src/i18n/index.ts` | Loads the files, sets `lang` and `dir` on `<html>`, and has `tr`, `msg`, `iso`, `formatDate` and `formatList` |
| Switching | `src/i18n/useLanguage.ts` | Saves the choice in app state and changes language |
| Switcher | `src/components/ui/LanguageSwitcher.tsx` | Used in the sidebar, landing, onboarding, the game header and the summary. Phones use the game header or ملفي |
| First paint | Script in `index.html` | Sets the saved direction before anything is drawn, so nothing flashes |

The preference is saved as `lang` in the `kw2` browser data. Older saved data has no `lang`, so it opens in Arabic with its progress unchanged.

Switching only re-renders. Nothing is reloaded or remounted, so timers, game state, the mascot and missions carry on.

## Add or change text

The file name is the first part of the key: `dashboard.json` with `{ "todayMission": "..." }` is `t('dashboard.todayMission')`.

1. Add the key to **both** `ar-SA` and `en`.
2. In a component, use `const { t } = useTranslation();` and `t('area.key')`.
3. Run `npm test`. It fails if a key is missing, if the languages use different variables, or if Arabic is hardcoded in `src/`.

To add a language, add a locale folder, add it to `LANGS` in `src/i18n/index.ts`, and add its direction to `isRtl`.

## Rules

**Keep IDs in state, and text out of it.** This is what lets a language change mid-game work.

```tsx
// Wrong: the bubble stays in the old language after a switch.
setBubble(t('games.mem.focus'));

// Right: a key, or a function when it needs values, turned into words when shown.
env.say('curious', 'games.mem.focus');
env.say('happy', () => tr('games.attention.left', { count: remaining }));
```

- Compare answers using stable values (`'sky'`), never displayed words.
- Inside a function that runs later, use `tr` from `src/i18n`. The `t` from `useTranslation` stays in the language it was created in.
- A function kept in React state needs wrapping: `setX(() => () => tr('key'))`.
- Mission reasons are saved as codes (`{ k: 'lastLow', acc: 40 }`) and written out by `whyText`. Plain strings are reasons saved by older versions and are shown as they are.

**Never translate what the user wrote.** Task text, typed cards, names and chat messages stay exactly as written, in any language. Use `dir="auto"` where they appear, and `iso()` or `<bdi>` when they sit inside a sentence.

Saved chat messages are records too. They stay in the language they were written in, and only a live control such as the confirmation card follows the switch.

**Plurals.** Use `count`, and give each language its forms: Arabic needs `_zero`, `_one`, `_two`, `_few`, `_many` and `_other`, and English needs `_one` and `_other`.

**Gender.** English is gender-neutral. In Arabic, use the user's stated form through `_m` and `_f` keys. Give English both keys too, with the same text.

**Don't build sentences by joining pieces.** Word order differs. Use a full sentence with variables, such as `games.mem.object`, which is `{{shape}} {{color}}` in Arabic and `{{color}} {{shape}}` in English.

## Direction

- Use logical CSS: `margin-inline-start`, `inset-inline-end`, `text-align: start`.
- Icons that point along the reading direction take `className="flip"`. Their art is drawn for right to left.
- Don't mirror the mascot, illustrations or clocks. Positions on top of a drawing stay physical (`left`, `top`) because the drawing doesn't mirror. See `AttentionSceneGame` and `CalmLandscapeGame`.
- Charts run in reading direction, using `isRtl()`.

## Companion and safety

- The app sends `context.lang` with each chat request, and the server tells the model through `reply_language`. If someone clearly writes in the other language, the model answers in that language.
- Crisis wording is checked in **both** languages, whichever is showing (`crisis.ts`).
- Support messages are in `companion.json` under `crisis`. They need clinical review in both languages, and the phone numbers must stay the same in both.
- `crisis.ts` and `server/chat.ts` also run on the server, so they import locale JSON directly instead of using i18next. If you change files under `server/` while `npm run dev` is running, restart it.
- Rule replies recognise keywords in both languages (`rules.ts`), and reply in the selected one.

## Known limits

- English copy hasn't had a native-speaker review, and Saudi Arabic copy still needs review by Saudi speakers.
- Numbers use Western digits in both languages, as the app already did, though some Arabic text spells out Arabic digits.
- The Latin letters come from IBM Plex Sans Arabic, so both languages share one font.
- Safari, real phones and screen readers haven't been tested in either language.
